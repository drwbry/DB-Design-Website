The Web Foundry Stack Map

How the website factory works from intake to launch to updates

Template repo + onboarding skill + shared infrastructure
Big Picture

One repeatable system for custom local business websites.

The skill turns client answers into a site plan. The template repo turns that plan into an Astro site. Sanity handles client-editable content. GitHub and Coolify publish the site. Cloudflare and Resend handle domains, protection, forms, and email.

Technology Stack

What each piece is responsible for.

Codex Skill

Walks the agent through discovery, planning, build, deployment, QA, and handoff.

Astro

Builds fast static pages from components, page files, styles, and Sanity data.

Sanity

Client-friendly CMS for hours, menus, galleries, services, testimonials, and content.

Cloudflare

DNS, Turnstile bot checks, optional email routing, and the shared form Worker.

Coolify

Pulls GitHub code, runs the build, serves the static site on the VPS with HTTPS.

Information the Skill Needs

These answers determine what gets built and which services are used.

Business Profile

  • Name, type, customer, service area
  • Primary goal: calls, bookings, walk-ins, credibility
  • Existing site and content to keep

Pages and Features

  • Home, About, Menu, Services, Gallery, Contact
  • Booking, reservations, invoice pay, gift cards
  • Any special forms or workflows

Editable Content

  • Hours, menu, services, gallery, team, testimonials
  • Anything the client wants to update themselves
  • Everything else stays hardcoded for simplicity

Forms

  • Form type and required fields
  • Destination email and any extra recipients
  • Turnstile site key and `site_id` routing

Design Inputs

  • Logo, colors, photos, references
  • Vibe words: cozy, bold, luxe, classic, modern
  • Assets needed before build

Domain and Launch

  • Domain name, registrar, DNS access
  • Email forwarding needs
  • Who will edit content after launch

Where Sanity Fits

Sanity is not the website host. It is the editing dashboard and content source.

  • ✓Each client gets a separate Sanity project and `production` dataset, so client content stays isolated.
  • ✓Astro fetches Sanity content during the build. The live site is still static and fast.
  • ✓Publishing in Sanity triggers a webhook to Coolify, which rebuilds the site with fresh content.
  • ✓Pages include fallback content so an empty CMS does not break the site.

Files to Know

The small handful of files that orient the whole system.

  • ✓src/config/site.js stores shared site constants: domain, `site_id`, Worker URL, Turnstile key, form subjects.
  • ✓src/pages/ contains site routes. Client sites use normal routes like `/`, `/services`, `/menu`, not `/showcase`.
  • ✓studio/schemaTypes/ defines what the client can edit in Sanity.
  • ✓worker/index.js receives form JSON, checks Turnstile, looks up KV, and sends emails.
  • ✓CLAUDE.md explains repo-specific conventions for future coding sessions.
  • ✓web-foundry-onboarding skill is the procedural launch checklist and must stay in sync with workflow changes.
  • ✓docs/intake-form.md is the raw question set that feeds the planning step.
  • ✓docs/cowork-intake-brief.md maps intake answers into build-plan decisions.
